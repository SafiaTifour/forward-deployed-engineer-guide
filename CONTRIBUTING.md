# Contributing

This repository is intentionally documentation-first and source-aware. Contributions should improve clarity, accuracy, or usefulness without adding unsupported claims.

## Before contributing

- Read the main guide and the source ledger.
- Prefer public, primary sources.
- Distinguish facts, opinions, synthesis, and hypothetical examples.
- Mark illustrative scenarios as fictional.

## Good contributions

- Factual corrections with links to primary sources.
- Clarifications that improve accessibility or technical precision.
- Better examples, diagrams, or templates for evaluation and deployment.
- Documentation improvements that reduce ambiguity for newcomers.

## Avoid

- Claims of personal authority or industry expertise that are not evidenced.
- Invented client examples, quotes, dates, or deployment outcomes.
- SEO stuffing or marketing language.
- Hidden claims about expert review or production readiness.

## Suggested workflow

1. Open an issue for larger changes or disagreements.
2. Keep edits narrow and clear.
3. Update linked sources if a factual claim changes.
4. Validate markdown links and JSONL case files before submitting.

## Issue templates

Use the issue templates in [.github/ISSUE_TEMPLATE](.github/ISSUE_TEMPLATE) for:
- factual corrections
- suggested resources or references

This repository is best maintained as a careful, public explainer rather than an authoritative or promotional document.
